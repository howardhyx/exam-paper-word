# 命题蓝图与评分分配

## 优先级与可行性

先满足范围、总分、题型/题数/单题分值、必考内容和其他用户明确要求；再尽量满足考点目标分值、预计难度分布、覆盖广度、重复控制和作答时间。明确要求的难度比例也可成为硬约束。不能擅自修改硬约束。

按固定题型可用分值和小问分值把比例转成可实现的分数。以用户给出的允许偏差为准；没有偏差约定时，将软性目标与实际分值并列解释，不把整数取整造成的差异悄悄抹平。若硬约束矛盾，列出具体冲突并只询问需调整的项。

## 权重形成

1. 把范围归整为可分配的板块。板块既可以是知识主题，也可以是课程中的主要能力；同一主分布的分类维度保持一致，避免“导数”和“推理能力”重叠相加。
2. 记录权重的依据：用户重点、单元/综合考试用途、课程核心要求、内容规模及核验过的参考样卷。
3. 确定板块目标分值，再把题型和预计难度资源分到各板块。用交叉表检查难度是否全部压在单一板块。
4. 给核心板块设置适当覆盖要求；细分内容允许轮换，不为每个碎片知识点单独凑题。
5. 用逐题命题卡落实预算。板块不必逐一获得易中难三档题，但整卷需符合目标。

可以使用“优先满足硬约束，再最小化软目标偏差”的计算方法。权重系数是本次设计选择，不是测量结论或官方标准。不要把一套固定百分比永久套用到所有学科。

## 分值归属和难度

- 从评分单位统计：一道客观题、一个小问或一个作文评分维度都可以是单位；视任务细化。
- 每个单位的 `topic_scores` 合计必须等于其分值。综合题分到多个考点时只分割原分值，不能给每个考点各计全分。
- 主分布之外，辅助考点、技能、情境类型可多标签记录覆盖，不参与满分求和。
- 预计难度按小问/评分单位统计。难度来自学生需要完成的任务，例如推理跨度、情境转换、信息整合、语言要求；不以题型或题分直接代替难度。
- 作文评价维度的分值不是互相独立的“易题/难题”。难以细分时，整道任务按一个预计难度计分，在说明中保留估计局限。
- “基础/进阶”“易/中/难”等标签都可由用户定义。无试做数据时，不提供伪精确的实测正确率或难度系数。
- 所有题型名称开放。单选、多选、填空、实验、阅读、翻译、材料分析、设计、实操、作文等无需映射成固定的三种题型。

## 多学科作答与评分

- 阅读/语言任务：核对原文、设问、语言水平、答案依据和字数要求。翻译/表达允许意思正确且符合要求的不同措辞。
- 史料/社会科学/人文论述：区分材料事实、解释及论证；评分要求说明证据与推理，而不是唯一观点。引文和真实事件可追溯。
- 写作/作品：建立与任务匹配的评分维度、档次描述和部分得分边界。示例作品不能等同于唯一正确答案。
- 数理/技术/实验：检查公式、条件、单位、图形、数据范围和可操作性；安全要求只在实际学科任务需要时处理。
- 地图/艺术/其他学科：按学科惯例检查图例、尺度、标注、图像质量、术语与材料来源。不要照搬数理题的解题步骤格式。
- 听力或音视频任务：确定播放材料或脚本是否可用，明确播放/施测要求；缺少材料时不把题目描述为已可直接施测。

这些是路由示例；没有列出的学科按其实际课程与评价要求处理。

## 可供脚本核对的数据结构

下列是分值结构示例，分配数值只用于说明字段。题干、解答、LaTeX、材料来源、图表和命题卡等存入同一记录，分值脚本不限制这些字段。完整试卷另在每道题上记录 `answer_spaces`，按 [答题空间记录与组件](answer-space-components.md) 估计并核对实际容量；无需独立作答区的题显式用空数组。下方示例仅示范分值检查，不是最终排版记录。

```json
{
  "total_marks": 10,
  "duration_minutes": 20,
  "allowed_topics": ["材料理解", "论证表达"],
  "requirements": {
    "types": {"材料分析": {"count": 1, "marks": 10}},
    "topics": {"材料理解": {"min": 4}, "论证表达": {"min": 6}},
    "difficulty": {"中": {"marks": 10}}
  },
  "targets": {
    "topics": {"材料理解": 4, "论证表达": 6},
    "difficulty": {"中": 10}
  },
  "questions": [
    {
      "id": "1",
      "type": "材料分析",
      "marks": 10,
      "estimated_minutes": 15,
      "units": [
        {
          "id": "1(1)", "marks": 4, "difficulty": "中",
          "topic_scores": {"材料理解": 4},
          "rubric": [
            {"criterion": "准确概括材料中的两项主要信息，每项2分", "marks": 4}
          ]
        },
        {
          "id": "1(2)", "marks": 6, "difficulty": "中",
          "topic_scores": {"论证表达": 6},
          "rubric": [
            {"criterion": "提出与问题相关且明确的观点", "marks": 2},
            {"criterion": "结合材料证据解释观点，按证据与解释完整程度给分", "marks": 4}
          ]
        }
      ]
    }
  ]
}
```

- `allowed_topics` 是本次主分值分布的全部合法分类标签，必须非空；范围的文字边界仍需人工审核。
- `requirements` 中仅填入硬约束；`types` 可用 `count`、`marks`、`each_marks`，`topics`/`difficulty` 可用 `marks`、`min`、`max`。数值单位均为分，不是百分比。
- `targets` 中是软性目标分值；脚本返回偏差，不将偏差直接判失败。
- `units` 不可为空，可对应小问或评分维度。`difficulty` 采用本次一致的标签。分值可为小数。
- `rubric` 在最终阶段必填，列出可实际给分的条件，合计等于单位分值。计划阶段允许暂缺。最终 `topic_scores` 必须根据已完成解答和采分点重算；脚本不能判断某个标签是否在学科上正确。
- 总分统计的是一个合法可作答组合。含选做题时，不把所有备选题加起来作为满分；为不同合法组合分别构造计分蓝图并核验。若组合导致考点分布不同，报告可达到的范围，不能只核验一个有利组合。
- 小数运算使用 Decimal，避免浮点误差。扣分和档次说明写在评分规则中；不要把负分混入正向采分点累计。额外加分、封顶和选做规则需要另行核对。

运行方式（替换为实际解释器和路径）：

```text
python scripts/check_blueprint.py work/blueprint.json --stage plan --report work/plan-check.json
python scripts/check_blueprint.py work/blueprint.json --stage final --report work/final-check.json
```

成功退出码为0；输入错误、分值错误或硬约束失败为1。报告包含总分、题型/考点/预计难度分布、时间估计、硬约束错误和软目标偏差。通过不代表题目正确、符合课程范围或难度已实测。
